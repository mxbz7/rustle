RUSTLE UI/UX UPDATE
==================

Implemented in this update
--------------------------
- Preserved the existing midnight-purple theme and current application architecture.
- Made the search experience a dedicated full-screen mode with its own header; the home screen no longer shows the search field by default.
- Preserved the conversation-list scroll position when leaving search.
- Updated profile display-name editing to use a compact in-app dialog instead of browser prompt/alert dialogs.
- Improved mobile viewport sizing, safe-area handling, scrolling, touch targets, and keyboard-aware screen height using the Visual Viewport API where available.
- Added a more robust photo viewer interaction layer with pinch zoom, double-tap zoom, and one-finger panning while the viewer is open.
- Kept long-press copy scoped to message text; timestamps and other message metadata remain outside the copy target.
- Added a startup failure fallback so a failed initialization is less likely to leave a blank screen.
- Updated the service worker cache version and hardened shell caching/update behavior.
- Added reduced-motion-aware dialog transitions and compact profile edit UI.

Files changed
-------------
- index.html
- style.css
- app.js
- sw.js

Validation performed
--------------------
- JavaScript syntax check: app.js passed (node --check).
- Service worker syntax check: sw.js passed (node --check).
- HTML parser check: passed; no duplicate element IDs found.
- CSS parser check (tinycss2): passed; no top-level parse errors found.

Limitations
-----------
- A full browser/device interaction test could not be completed in this environment; headless Chromium did not finish loading/returning the app DOM before the execution timeout.
- Nostr relay messaging, Supabase username registration, encrypted image transfer, and real Android keyboard behavior still need end-to-end verification on a deployed build and a physical Android device.
- Existing encryption, Nostr, Supabase, identity, and attachment logic was intentionally not rewritten.

Deployment
----------
1. Back up the currently deployed project.
2. Replace the deployed project files with the contents of this ZIP.
3. Deploy the complete project to the same static hosting location.
4. Open RUSTLE once while online so the new service worker can install and activate.
5. If an installed PWA appears stale, fully close and reopen it after the service worker update completes.
6. Verify chat send/receive, profile editing, username registration, photo transfer, and photo viewer gestures on a real Android device.


==================================================================
UPDATE: HEADER PROFILE TAP, BADGE ALIGNMENT, THREE-DOT MENU
==================================================================
Files changed: index.html, style.css, app.js, sw.js (cache rustle-shell-v25 -> v26)

1. Chat header: tapping the @username (or the avatar) opens the existing contact
   profile sheet for the current conversation. The verified badge keeps its own
   handler (shows the verification card) and never opens the profile. The
   verification card now opens below the badge in the header and is kept inside
   the viewport. Renaming a contact no longer drops the badge from the header.
2. Contact sheet: username and badge share one flex row (vertically centred, 7px
   gap, name truncates with an ellipsis); the npub sits underneath. A previous
   contact's badge can no longer linger when the sheet is reused.
   The empty-chat intro uses the same row.
3. Three-dot button: compact floating menu (Clear chat, View profile) anchored to
   the icon inside the conversation screen. Closes on outside tap, selection,
   Escape, back-arrow and resize. No bottom sheet, no navigation.
   - Clear chat asks for confirmation, deletes this contact's local messages and
     locally stored photos only, keeps the contact/profile/identity, and stores a
     "cleared at" timestamp (data.clearedAt[pubkey]) so older events re-fetched
     from relays are not re-imported. Nothing is deleted on relays or on the
     other person's device.
   - Block was NOT added: the app has no blocking feature.

Tested (headless Chromium via Playwright, 360/390/430px, seeded local data):
 name tap, avatar tap, header badge tooltip (no profile), sheet alignment,
 menu position/in-viewport, outside-tap/Escape/toggle close, View profile,
 clear-chat cancel + confirm, contact/other chats intact, tombstone filtering
 of old events, unverified contact shows no badge, zero page errors.
NOT tested: real Android device, hardware back button, live Nostr relays,
 Supabase, encrypted photo transfer, installed-PWA service-worker update.
